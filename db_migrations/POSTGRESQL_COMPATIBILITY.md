# SQLite catalog → PostgreSQL compatibility review

Reviewed against `memory/agent_memory/frankensqlite.db` on 2026-09-19. This is
the migration baseline review, not proof that the application has completed
its runtime cutover.

| SQLite construct in catalog | PostgreSQL mapping | Status |
| --- | --- | --- |
| `INTEGER PRIMARY KEY AUTOINCREMENT` | `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | Supported; sequence reset after copy. |
| Other `INTEGER` / `REAL` | `BIGINT` / `DOUBLE PRECISION` | Supported. |
| `DATETIME` | `timestamp without time zone` | Supported; preserves Vietnam-local legacy wall time. |
| `BOOLEAN DEFAULT 0/1` | `BOOLEAN DEFAULT FALSE/TRUE` | Supported; importer rejects values other than 0/1/boolean. |
| `*_json TEXT` | `JSONB` | Supported; importer parses every non-null value and fails on invalid JSON. |
| `json_extract(payload_json, '$.key')` index expressions | `(payload_json ->> 'key')` | Supported for the current simple dotted-key expressions. |
| `UNIQUE`, partial indexes, `CHECK`, and FK | Preserved; boolean `0/1` predicates become `FALSE/TRUE` | Supported by PostgreSQL 17. |
| `CURRENT_TIMESTAMP` | Preserved | Supported; it produces a naive timestamp in a `timestamp without time zone` column. |

## Catalog boundaries

The current catalog does **not** contain `COLLATE NOCASE`, `WITHOUT ROWID`,
`STRICT`, generated columns, FTS/virtual tables, SQLite `datetime()` defaults,
or SQLite-only conflict clauses in its table/index DDL. If any are added before
the cutover, extend the translator and the tests first.

The importer only recognizes JSON columns by the established `_json` suffix and
only translates `json_extract(column, '$.key')` expression indexes. This is
intentional: silently guessing that arbitrary text contains JSON would turn a
controlled migration failure into data loss.

## Runtime blockers (outside this importer)

This validates storage import only. Production code still needs dialect and
driver migration: SQLite `?` parameters, `datetime('now')`, `strftime`,
`julianday`, `INSERT OR IGNORE`, `rowid`, PRAGMAs, and synchronous
`better-sqlite3` calls are not PostgreSQL runtime-compatible. Keep the SQLite
source read-only as fallback until those application integration tests pass.
